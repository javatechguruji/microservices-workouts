# Order-service Swagger reference

Swagger is retained only in **order-service**. For cross-service business scenarios,
UI actions, Kafka topics and consumers, use the main
[business-flow reference](../project-docs/business-flows-and-service-dependencies.md).

## Open and inspect

1. Reload Maven in IntelliJ to resolve the order-service springdoc dependency.
2. Start PostgreSQL and order-service using its local profile, following
   [commerce setup](../infra-setup/commerce-setup.md). Restart an existing process
   after the new dependency/configuration is built.
3. Open **http://localhost:9101/swagger-ui.html**. Its generated OpenAPI JSON is
   **http://localhost:9101/v3/api-docs**.
4. Expand an operation for its purpose, request model, example where supplied,
   permissions, callers, outbound service calls and asynchronous effects.

The UI is intentionally **read-only** (`supported-submit-methods: []`). Execute
business requests from React or Postman through gateway on 9100 using a Keycloak
Bearer token. Trusted `X-Auth-*` headers are generated by gateway and are hidden
from the documentation inputs. Static example prices/IDs are illustrative, not live quotes.

`documentation.gateway-url` is profile-specific and defaults to
`http://localhost:9100`; override with `PUBLIC_GATEWAY_URL` if the exposed gateway
address changes. It describes the destination for business calls. Browsing the
order-service documentation itself does not require gateway or a token.

Docs/UI assets are public in this learning service. No Swagger dependency, spec
proxy route or UI was added to the other eight services. No broader gateway security
or CORS exception was retained for Swagger.

## Documented operations

| Method and path                              | Purpose                                                           |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `POST /api/orders`                           | Legacy amount-only order creation.                                |
| `GET /api/orders`                            | List orders permitted by owner/tenant policy.                     |
| `GET /api/orders/{id}`                       | Read one authorized order.                                        |
| `PATCH /api/orders/{id}/status`              | Admin legacy status update; shopping orders must use fulfillment. |
| `GET /api/orders/security/me`                | Inspect trusted identity; portal bootstrap.                       |
| `GET /api/orders/security/admin`             | Admin RBAC demonstration.                                         |
| `GET /api/orders/{id}/inventory/{sku}`       | Order-authorized inventory lookup with service credentials.       |
| `POST /api/orders/checkout`                  | Accept shopping order/items and durable checkout with HTTP 202.   |
| `GET /api/orders/{id}/fulfillment`           | Observe saved items, workflow state and tracking.                 |
| `POST /api/orders/{id}/fulfillment/{action}` | Admin ship/deliver transitions.                                   |

## Implementation and verification

- [OpenApiConfiguration](../../order-service/src/main/java/com/tip/ecommerce/order/OpenApiConfiguration.java)
  defines metadata, gateway destination and Bearer scheme.
- [OrderController](../../order-service/src/main/java/com/tip/ecommerce/order/controller/OrderController.java)
  and [CheckoutController](../../order-service/src/main/java/com/tip/ecommerce/order/controller/CheckoutController.java)
  contain the operation descriptions; DTOs/records supply request/response structure.
- [HeaderAuthorizationConfig](../../order-service/src/main/java/com/tip/ecommerce/order/security/HeaderAuthorizationConfig.java)
  exempts only documentation paths in addition to existing health/error paths.
  Business APIs retain their current permission checks.

```sh
# Run from workspace root with JDK 17 and PostgreSQL available.
mvn -f order-service/pom.xml -Dtest=OpenApiDocumentationTest test
```

The test reads all ten operations, checks trusted headers are not exposed as inputs,
loads the Swagger page and checks read-only UI configuration. It disables scheduled
workers, Kafka consumption and schema writes, and writes the generated spec to
`order-service/target/openapi.json`. It does not place an order or publish an event.

[Springdoc's documentation](https://springdoc.org/v2/) covers the compatible 2.8.x
line for Spring Boot 3.5.x and Swagger UI options.
